Top 10 Viva Questions & Answers (KKWIEER Syllabus Defense)

Mini Project Defense

Q1: Why did you choose a Tree structure rather than a Graph for course prerequisites?

A tree provides a strict hierarchy centered on a specific target course as the root. Tree height directly models the critical prerequisite chain (minimum sequential semesters required); leaf nodes immediately pinpoint foundational entry points; post-order cleanly rolls up credit sums; and pre-order creates intuitive visual branches.

Q2: Why are shared prerequisites repeated under different branches in the prerequisite tree?

In a true tree, every node (except the root) must have exactly one parent. For example, in Augmented Reality and Virtual Reality [2301306B], both Data Structures Lab [2301215] and OOP & CG Lab [2301205] require Programming in C [2300108A]. Pointing both parents to a single shared node would create multiple parent edges, making it a Directed Acyclic Graph (DAG). Replicating the node preserves true tree properties and allows independent subtree traversals.

Q3: What is the primary limitation of a Tree compared to a DAG for course prerequisites?

The fundamental trade-off is node duplication. In dense prerequisite networks, shared foundational courses are replicated across multiple subtrees, causing the tree node count to exceed the number of unique courses (e.g. AR & VR has 11 subtree nodes for 7 unique prerequisites). A DAG avoids repetition, but requires general graph algorithms like Kahn's or Tarjan's.

Q4: Walk through the longest prerequisite chain in the KKWIEER syllabus.

The maximum tree height in the entire syllabus is 5 semesters. A prime example is Deep Learning [2301401]: Sem 2: Computational Thinking and Problem Solving [2300118A] → Sem 4: Data Structures [2301212] → Sem 5: Database Management Systems [2301303] → Sem 6: Data Science and Big Data [2301311] → Sem 7: Deep Learning [2301401].

Q5: Which course in the KKWIEER syllabus is the most critical bottleneck?

Data Structures [2301212] in Semester 4 is the largest academic bottleneck, having 8 direct dependents: DSA [2301301], AI [2311302], DBMS [2301303], DBMS Lab [2301304], AR & VR [2301306B], AR & VR Lab [2301307B], High Performance Computing [2301315C], and Operation Research [2301406A].

Q6: How are Elective Groups handled during post-order credit summation?

Courses belonging to the same elective group (e.g. Elective I in Sem 5: IoT, AR/VR, STQA) are academic alternatives. In our Curriculum Tree, an intermediate isElectiveGroup node sits between Semester and Course. During post-order traversal, the group node takes the credit value of its first child (e.g. 3 credits) once, rather than summing all alternatives, guaranteeing the semester total matches exactly (22 credits) and degree total equals 172 credits.

Q7: How do you check that prerequisites are always in earlier semesters using Tree concepts?

We do not use graph topological sort. Instead, each course node in the Curriculum Tree maintains a parent pointer. By following parent pointers upwards until reaching a Semester X node, we extract the semester number of the course and its prerequisite in $O(h)$ time, and assert that prereqSemester < courseSemester.

Q8: How does cycle detection work during tree construction?

During recursive tree construction (buildPrereqTree), we pass a visitingSet representing the current recursion call stack. If a course code is encountered that already exists in visitingSet, a circular dependency is immediately detected and recursion safely stops, preventing infinite call stack overflow.

Q9: How is Lowest Common Ancestor (LCA) computed in the Curriculum Tree?

Using parent pointers, we trace paths from Course A and Course B back to the degree root. We then align the two path vectors from the root downwards; the last identical ancestor node before paths diverge is the LCA. If the LCA is a Semester, both courses can be taken concurrently; if a Year, they belong to the same academic year; if Degree, they belong to different years.

Q10: How does the Undo feature operate?

It employs the Command Pattern backed by an std::stack<UndoAction>. Whenever a course or prerequisite is added or removed, the previous state is pushed onto the stack. Selecting "Undo" pops the top action and executes its exact inverse operation in $O(1)$ time, safely rebuilding tree parent-child linkages and recalculating credit rollups.
